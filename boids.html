Background

What are Boids?

Boids (Bird-oid Objects) is a model of flocking behaviour created by Craig Reynolds in 1986. Each agent follows only three steering rules applied to its local neighbourhood — no agent knows the global state of the flock.

The result is emergent complexity: realistic flocking, splitting around obstacles, and regrouping, all arising from simple maths and proximity checks alone.

Reynolds' key insight was that flocking is a distributed computation. This maps directly onto modern multi-drone systems, where latency and communication range prevent any single controller from commanding every vehicle.

Rule 1

Separation

Each boid steers away from any neighbour that is closer than the crowd radius \(r_s\). Without this rule, the flock collapses into a single point; with it, agents maintain comfortable spacing.

Separation Steering Vector
$$\vec{s}_i = \sum_{\substack{j \in \mathcal{N}_i \\ d_{ij} < r_s}} \frac{\vec{p}_i - \vec{p}_j}{\|\vec{p}_i - \vec{p}_j\|^2}$$
Where
$$d_{ij} = \|\vec{p}_i - \vec{p}_j\|, \quad r_s = \frac{r_f}{1.3}$$

The inverse-square weighting \((1/d^2)\) makes very close neighbours produce a much stronger repulsion than distant ones — the boid urgently dodges whatever is right next to it while barely noticing agents near the boundary.

Rule 2

Alignment

Each boid steers to match the average heading of its neighbours within the perception radius \(r_f\). Velocity contributions are distance-weighted so closer neighbours have more influence.

Alignment Steering Vector
$$\vec{a}_i = \sum_{\substack{j \in \mathcal{N}_i \\ d_{ij} < r_f}} \frac{\hat{v}_j}{d_{ij}}$$
Normalised velocity & neighbour set
$$\hat{v}_j = \frac{\vec{v}_j}{\|\vec{v}_j\|}, \quad \mathcal{N}_i = \{ j \neq i : d_{ij} < r_f \}$$

Dividing by \(d_{ij}\) instead of averaging gives nearer boids proportionally more weight. This creates a local-first alignment that is robust to outliers at the periphery — important for real swarms with patchy communication.

Rule 3

Cohesion

Each boid steers toward the centre of mass of its neighbourhood, keeping the flock together as a loose whole. Without cohesion, separation and noise alone would scatter agents indefinitely.

Centre of Mass
$$\bar{\vec{p}}_i = \frac{1}{|\mathcal{N}_i|} \sum_{\substack{j \in \mathcal{N}_i \\ d_{ij} < r_c}} \vec{p}_j$$
Cohesion Steering Vector (from source)
$$\vec{c}_i = (\bar{\vec{p}}_i - \vec{p}_i)\Big|_{\|\cdot\|=0.05}$$
Note
$$r_c = r_f = 60 \times \text{scale} \quad \text{(cohesion uses friend radius)}$$

The magnitude is clamped to 0.05 (setMag(0.05) in the source) so cohesion is a gentle pull — strong enough to resist scatter but soft enough to let separation win at short range, preventing pile-ups.

Application

From Boids to Drone Swarms

Boid rules translate directly into drone swarm controllers. Each rule maps to a physical requirement already present in multi-UAV operations.

Separation → Collision Avoidance

Minimum safe separation between drones is enforced by the same inverse-square repulsion used in the boid model. In practice this is augmented by ADS-B/UWB ranging and hard physical limits on manoeuvre rates.

Alignment → Formation Holding

Drones in a formation match bearing and airspeed with neighbours. IMU/GNSS heading fusion provides the velocity vector equivalent to the boid's move variable, broadcast over MAVLink.

Cohesion → Flock Integrity

Gentle centripetal acceleration keeps the swarm from dispersing over a wide area. In real systems this is tuned to the comms range — drones at the edge of reliable link budget get a stronger pull-back.

Obstacle Avoidance → Geofence / Terrain

The Avoid objects in the Processing sketch model static obstacles. Drone swarms extend this with live 3-D point-cloud data from onboard LiDAR/depth cameras for dynamic obstacle fields.

Noise → Resilience & Exploration

The random perturbation term prevents lock-in to degenerate configurations (all drones flying in a single line) and lets the swarm re-explore after an obstacle splits the flock.

No Central Controller

The boid model is inherently decentralised — exactly the failure-tolerant architecture required for GPS-denied or communication-degraded environments in real tactical swarms.
